DDS /d/<token> NestJS · spec §9 · ADR 0003 · design note, not a screen

This route renders no page, and that is the design

When a Requester follows the link in the delivery email, NestJS counts the Attempt, checks the token, and then either streams the archive immediately or redirects to /link-expired. There is no "your download is starting" interstitial, because an interstitial makes collection depend on a page rendering — which is the one thing §9.1 forbids.

The two things a user actually experiences here

The filename that lands in their downloads folder

This is the whole of the route's user interface — the only thing the Requester sees and keeps. The format is §8.3's, stamped from the time the Request was submitted, in Asia/Bangkok.

dds-envocc-sharing-20690828-075012.zip

Each re-run appends -r2, -r3, so two files from one Request never collide.

Open question for the repo owner · recorded on #51

§16.2 lists /link-expired as an Angular route, but §9.1 requires the collection path to work when the Angular bundle fails to load — and /link-expired is exactly where this route redirects. The two sections point opposite ways.

This design does not resolve it, because it is a serving decision and not a visual one. What it does instead is make the page renderable either way: no Angular component, no JavaScript, and nothing but the one compiled stylesheet both runtimes already serve.
