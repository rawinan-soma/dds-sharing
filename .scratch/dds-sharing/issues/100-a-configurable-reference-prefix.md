# A configurable reference prefix

Status: ready-for-agent
Labels: enhancement

> *This was generated by AI during triage.*

## What to build

**Category:** enhancement
**Summary:** The prefix of a Request's reference number comes from configuration, so the Pilot issues `PLT-2569-0142` while Production keeps `REQ-2569-0142`.

**Current behaviour.** Every deploy stamps references as `REQ-<Buddhist-era year>-<four-digit counter>` (spec §12.5), with `REQ` fixed in the code that formats them. The Pilot (ADR 0022, CONTEXT.md) is a second service with its own record and counter, so both services would issue the same numbers — and a reference is quoted over the telephone, where it has to say by itself which service holds the Request.

**Desired behaviour.**

- A new optional setting, `REFERENCE_PREFIX`, validated at boot with the rest of the environment (the ConfigModule schema): two to eight upper-case ASCII letters, **defaulting to `REQ`**. Anything else is a boot failure, like every other invalid setting — never a silent fallback to the default.
- The reference formatter takes the prefix; the shape stays `<PREFIX>-<year>-<counter>`, and the year and counter rules of §12.5 are unchanged.
- Nothing else parses a reference by its prefix. The lookup (#97) already matches the whole reference exactly, so a Production lookup of a `PLT-` number finds nothing and vice versa — that stays true and gets a test.
- `.env.example` documents the setting and says why it exists: one prefix per service that keeps its own record.
- Spec §12.5 gains one sentence: the prefix is configuration, `REQ` by default, `PLT` on the Pilot (ADR 0022).

**Key interfaces.**

- The reference formatter (today `formatReference(submittedAt, counter)`) gains the prefix as an input; the service that stamps a Request at submit passes the configured value.
- The environment schema gains `REFERENCE_PREFIX` with its default beside the other defaulted settings.

## Acceptance criteria

- [ ] With `REFERENCE_PREFIX` unset, a submitted Request's reference is `REQ-<year>-<counter>`, exactly as today
- [ ] With `REFERENCE_PREFIX=PLT`, a submitted Request's reference is `PLT-<year>-<counter>`, and the confirmation page, the emails and the Reviewer surface all show it
- [ ] A `REFERENCE_PREFIX` that is not two to eight upper-case ASCII letters fails boot with a message naming the setting
- [ ] The lookup by reference finds a `PLT-` Request by its full reference, and finds nothing for the same number under `REQ-`
- [ ] `.env.example` and spec §12.5 describe the setting

## Out of scope

- Deploying the Pilot, or setting the value anywhere but `.env.example` (#101)
- Changing the year or counter parts of the reference, or what the counter resets on
- Migrating or rewriting any reference already stored
