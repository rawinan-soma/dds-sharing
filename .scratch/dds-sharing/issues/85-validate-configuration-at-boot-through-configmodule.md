# Validate configuration at boot through ConfigModule

Status: closed
Blocked by: 64
Labels: enhancement
Source: https://github.com/rawinan-soma/dds-sharing/issues/85 (migrated 2026-09-21)

> *This was generated by AI during triage.*

## Request

Validate the API's configuration when it starts, through `ConfigModule`, so a missing or malformed setting fails boot instead of degrading silently.

## Where things stand

- `apps/api/src/app.module.ts` loads `ConfigModule.forRoot({ isGlobal: true })` with no validation, and nothing reads config through `ConfigService`.
- Four variables are read straight from `process.env`, some with silent fallbacks:
  - `DATABASE_URL` falls back to a hard-coded localhost URL in `drizzle.config.ts`
  - `PORT` falls back to `3000` in `main.ts`
  - `APP_DATABASE_URL` is checked by hand in `province-integrity.service.ts`
  - `FAKE_UPSTREAM_PORT` is read by the fake harness
- `docker-compose.yml` already passes `REDIS_URL`, `MINIO_*` and `SMTP_*`, which no code reads yet.

## What the SRS already requires

- **NFR-31:** SMTP settings, `FRONTEND_URL` and the upstream bearer token come from config, and "no insecure setting is reachable by silent degradation".
- **OQ-01:** confirm `SMTP_PORT` rather than defaulting it silently.
- **NFR-32:** boot failures are failures, never warnings.
- **§2.4.1:** `class-validator` / `class-transformer` are the chosen validation stack; neither is installed in `apps/api` yet.
- #68, #71, #72 and #77 each add config that would build on this.

## Settled in triage

Every open question was settled in triage. **The spec is the [Agent Brief](https://github.com/rawinan-soma/dds-sharing/issues/85#issuecomment-5658764349) as changed by its [amendment](https://github.com/rawinan-soma/dds-sharing/issues/85#issuecomment-5658972066).** Nothing below is open.

1. **Validation mechanism:** Joi schema groups, passed to `ConfigModule` as `validationSchema` with `abortEarly: false`. `class-validator` stays with request and response bodies (FR-04).
2. **Scope:** the full set now. Features that use the new namespaces stay out of scope.
3. **Defaults:** only `PORT`, `ALLOW_INSECURE_TRANSPORT` and `SMTP_ALLOW_PLAINTEXT` have them. Every other variable is required, including `SMTP_PORT` (OQ-01).
4. **Rollout:** every direct `process.env` read moves behind validated config, and a lint rule bans new ones. Code outside Nest validates its own group before reading.
5. **Tests and CI:** a checked-in `.env.test` loaded through Vitest setup. CI overrides only the database URLs.

## Agent Brief

**Category:** enhancement
**Summary:** Validate every environment variable at boot with Joi, expose it through namespaced config factories, and make direct `process.env` reads a lint error

**Read first:** ADR 0018 (*the environment holds deployment facts, not policy*), spec §10.5, §11.2, §13.2, §17.3, §17.5, and **Operator** in `CONTEXT.md`.

**Sequencing:** start after #64 (PR #84) has merged. #84 adds reads this ticket migrates.

**Current behavior:**
`ConfigModule.forRoot({ isGlobal: true })` is loaded with no validation, and nothing reads `ConfigService`. Variables are read straight from `process.env` in the HTTP bootstrap (`PORT`), the database client factory (which silently falls back to `DATABASE_URL`), the migration runner, the province integrity check (a hand-written `APP_DATABASE_URL` guard), Drizzle Kit's config (a hard-coded localhost fallback) and the fake upstream harness. After #84, the Reviewer CLI, a database provider factory and the cookie options add more, including `REVIEWER_INSECURE_COOKIES` and `REVIEWER_CLI_OPERATOR`. The single compose file hard-codes dev values, CI sets only the two database URLs, and an app-booting e2e spec would fail once validation exists.

**Desired behavior:**

*Validation.* One schema module defines Joi schemas in groups: `app`, `db`, `redis`, `minio`, `smtp`, `upstream`, `transport`, and a dev-only `fakeUpstream`. Each process validates only the groups it needs, with `abortEarly: false`:
- **HTTP app** (through `ConfigModule`'s `validationSchema`): app, db (**`APP_DATABASE_URL` only, never `DATABASE_URL`**), redis, minio, smtp, upstream, transport
- **Migration runner:** `DATABASE_URL`
- **Drizzle Kit config:** `DATABASE_URL`
- **Host CLI entrypoints:** `DATABASE_URL`, plus whatever the command needs
- **Fake upstream harness:** `FAKE_UPSTREAM_PORT`

Validation runs before anything migrates, connects or listens. On failure the process exits non-zero, listing **every** problem by variable name and **never printing a value**.

*Inventory and rules.* Every variable is required with no default, except the three noted.

| Variable | Rule |
|---|---|
| `PORT` | integer 1–65535, **default 3000** |
| `DATABASE_URL`, `APP_DATABASE_URL` | URI, scheme `postgres` or `postgresql` |
| `REDIS_URL` | URI, scheme `redis` or `rediss` |
| `MINIO_ENDPOINT` | hostname, no scheme, no port |
| `MINIO_PORT`, `SMTP_PORT`, `FAKE_UPSTREAM_PORT` | integer 1–65535 |
| `MINIO_USE_SSL`, `SMTP_STARTTLS`, `SMTP_SECURE` | strictly `true` or `false` |
| `MINIO_ACCESS_KEY`, `MINIO_SECRET_KEY`, `SMTP_USER`, `SMTP_PASS`, `UPSTREAM_TOKEN` | non-empty, no leading or trailing whitespace |
| `MINIO_BUCKET` | S3 bucket-name rules (3–63 chars, lowercase, digits, hyphens) |
| `SMTP_HOST` | hostname |
| `SMTP_FROM` | email address |
| `FRONTEND_URL` | URI, origin only (no path, query or trailing slash); `https` unless `ALLOW_INSECURE_TRANSPORT=true` |
| `UPSTREAM_BASE_URL` | URI, path prefix allowed; `https` unless `ALLOW_INSECURE_TRANSPORT=true` |
| `ALLOW_INSECURE_TRANSPORT` | strictly `true` or `false`, **default `false`** |
| `SMTP_ALLOW_PLAINTEXT` | strictly `true` or `false`, **default `false`** |

Cross-field rules:
- `SMTP_STARTTLS=false` with `SMTP_SECURE=false` fails unless `SMTP_ALLOW_PLAINTEXT=true`.
- `SMTP_STARTTLS=true` with `SMTP_SECURE=true` always fails.

*Insecure flags.* When `ALLOW_INSECURE_TRANSPORT` or `SMTP_ALLOW_PLAINTEXT` is `true`, boot logs a `WARN` line naming the flag, and `/health` reports which insecure flags are on. `ALLOW_INSECURE_TRANSPORT` replaces #84's `REVIEWER_INSECURE_COOKIES`: the session cookie's `Secure` attribute is off only when it is `true`.

*Reading config.* Services receive config through namespaced factories (`registerAs`) injected as `ConfigType<typeof …>`, one per group, each mapping validated variables to a typed object (e.g. `smtp` → `{ host, port, startTls, secure, user, pass, from }`). A service injects only the namespace it needs. The HTTP app has no namespace exposing `DATABASE_URL`.

*Direct reads banned.* A lint rule makes `process.env` an error everywhere except the schema and factory module, the non-Nest entrypoints listed above, and test setup. Every existing direct read moves behind validated config, including #84's. The database client factory loses its `DATABASE_URL` fallback, and Drizzle Kit's config loses its localhost fallback.

*The Operator.* `REVIEWER_CLI_OPERATOR` is removed. Every host command that writes an audit event takes a required `--operator <name>` argument and refuses to run when it is missing or blank. The operator is never inferred from the OS login.

*Environments.*
- `docker-compose.yml` is production-shaped: app, Postgres, Redis and MinIO, with the app's variables interpolated as `${VAR:?}` so Compose refuses to start when one is unset. On the VM, values come from a gitignored `.env`.
- `compose.dev.yml` adds Mailpit, the fake upstream as a service (`UPSTREAM_BASE_URL` pointing at it) and dev values, including both insecure flags. Dev runs `docker compose -f docker-compose.yml -f compose.dev.yml up`. **Do not use `compose.override.yml`**: Compose loads it automatically, so a VM checkout would pick up dev settings silently.
- A checked-in `.env.test` holds dummy values for every variable and is loaded through Vitest setup for the unit and e2e configs. CI keeps overriding only the database URLs.
- A checked-in `.env.example` lists every variable with a comment.

**Key interfaces:**
- Joi schema groups (named above), exported for reuse by every entrypoint
- Namespaced config factories: `app`, `db`, `redis`, `minio`, `smtp`, `upstream`, `transport`
- `ConfigModule.forRoot({ isGlobal: true, validationSchema, validationOptions: { abortEarly: false }, load: [...] })`
- The `/health` document gains a field listing insecure flags that are on; its four components are unchanged
- Host CLI commands: a required `--operator <name>` argument

**Acceptance criteria:**
- [ ] The HTTP app refuses to boot when any required variable is missing, and the error lists every missing or invalid variable at once
- [ ] Boot fails before migrations run or the port opens
- [ ] A test boots with a `.env.test`-shaped environment whose secrets are sentinel strings, breaks several variables, and asserts no sentinel appears in the error output
- [ ] Schema tests cover, each failing boot: missing `SMTP_PASS`; `SMTP_STARTTLS=false` + `SMTP_SECURE=false` without `SMTP_ALLOW_PLAINTEXT`; `SMTP_STARTTLS=true` + `SMTP_SECURE=true`; `http://` `FRONTEND_URL` without `ALLOW_INSECURE_TRANSPORT`; `FRONTEND_URL` with a path or trailing slash; `MINIO_ENDPOINT` with a scheme; a boolean given as `1` or `yes`; a secret with trailing whitespace
- [ ] A missing `ALLOW_INSECURE_TRANSPORT` yields a `Secure` session cookie, and `ALLOW_INSECURE_TRANSPORT=true` permits `http` URLs and a non-`Secure` cookie
- [ ] With either insecure flag on, boot logs a `WARN` naming it and `/health` reports it; with both off, `/health` reports none
- [ ] The HTTP app's injectable config exposes no `DATABASE_URL`
- [ ] A test asserts every variable a config factory reads is present in the schema
- [ ] `process.env` outside the allowed locations fails lint, and no such read remains
- [ ] The migration runner and Drizzle Kit config validate `DATABASE_URL` and have no fallback
- [ ] `REVIEWER_INSECURE_COOKIES` and `REVIEWER_CLI_OPERATOR` no longer appear anywhere
- [ ] Host commands that write an audit event refuse to run without `--operator`, and the event records the value given
- [ ] `docker compose -f docker-compose.yml -f compose.dev.yml up` brings the service up with the SPA at `/` and the API under the prefix; `docker compose up` without the dev file and without a `.env` refuses to start, naming the unset variables
- [ ] No `compose.override.yml` exists
- [ ] `.env.example` lists every variable in the inventory with a comment; `.env.test` is checked in; `.env` stays gitignored
- [ ] CI is green with only the database URLs overridden

**Out of scope:**
- Making policy tunable through the environment: `N`, the 72-hour Download token expiry, session limits, the collection-lapse trip-wire, upstream timeout and retry values, the de-identification allowlist. These stay reviewed constants (ADR 0018).
- Real production values and the VM's `.env` (#77)
- Using the new SMTP, MinIO, Redis or upstream config in features: those tickets consume the namespaces; this one only defines and validates them
- Validating request and response bodies (`class-validator` / `class-transformer`, FR-04)
- Moving the SPA into its own container — considered and declined; one container per ADR 0003 stands
- Adding the Operator as an Actor kind (tracked separately)
